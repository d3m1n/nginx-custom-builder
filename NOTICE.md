## Local deviations from the vendored pkg-oss skeleton

1. `nginx.postinst` — added an `nginx -t` configuration-validation guard
   before any service start/upgrade action. Upstream pkg-oss starts/upgrades
   the service unconditionally; we must never (re)start nginx with a broken
   configuration (project safety requirement). On validation failure the
   service is left untouched and the operator gets an explicit message.
2. `nginx.control.in` — the generated `debian/control` drops the separate
   `nginx-dbg` package stanza (project requirement: ONE `.deb` artifact per
   target/version). The `nginx-debug` binary itself is still built and shipped
   inside the main `nginx` package, keeping runtime parity with nginx.org
   packages (which do ship `nginx-debug` in the main package).
3. `debian/changelog` and maintainer identity are generated by this project's
   build scripts (upstream generates them from its own docs tooling).

## Package removal semantics (important, from the vendored skeleton — nginx.org parity)

- `dpkg -r nginx` / `apt remove nginx` (ordinary removal): **removes nothing**
  from `/etc/nginx`, logs, or cache. User configuration, certificates and logs
  are preserved.
- `dpkg -P nginx` / `apt purge nginx` (explicit purge): deletes `/etc/nginx`,
  `/var/log/nginx`, and `/var/cache/nginx` entirely. **Back up certificates
  and configuration before purging.** This matches official nginx.org package
  behavior.
